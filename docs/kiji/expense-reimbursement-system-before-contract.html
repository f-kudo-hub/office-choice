経費精算システムの導入、総務が契約前に決める承認ルートと過去データの持ち出し

2026-09-28　経費精算電子帳簿保存法クラウドサービス総務の稟議解約条件

この記事で紹介しているのは、申し込む形のサービスです。現在、アフィリエイトの提携はありません。

経費精算システムの比較で最初に目が行くのは、月額とスマホアプリの使いやすさです。ですが、後から効いてくるのは別のところにあります。承認ルートを誰がどう作るか、領収書の原本をいつ捨てられるか、解約したあと過去の精算データをどう取り出すか。この3つを契約前に決めておくと、稟議も運用も通りやすくなります。この記事を読み終えるころには、見積書のどこを見て、どの質問をベンダーに投げればよいかが決まっている状態を目指します。

システムを選ぶ前に、承認ルートを紙に書き出す

よくあるのは、システムを決めてから承認の流れを考え始めるパターンです。順番が逆になると、設定の段階で止まります。

先に決めるのは次の点です。

  • 申請者の上長は誰か。兼務や部署をまたぐ人はどう扱うか
  • 金額がいくらを超えたら、役員や社長の承認を足すか
  • 経理の最終チェックは、承認の前か後か
  • 承認者が不在のとき、誰が代わりに押すか

ここが曖昧なまま導入すると、承認が特定の1人に集中します。月末に数十件が滞留して、結局「紙のほうが早かった」という声が出ます。導入後につまずく会社の多くは、システムの性能ではなく、この流れの設計で止まっています。

もうひとつ、紙に書いてみると気づくことがあります。今の運用が、実は規程どおりになっていないことです。規程では部長承認なのに、実際は課長が押している。システムは規程どおりにしか動かせないので、導入は規程を直す機会にもなります。社内で反発が出るとすれば、たいていこの「今までどおりが通らなくなる」点です。先に経営層と握っておくほうが、後で揉めません。

電子帳簿保存法の対応は「スキャナ保存」と「電子取引」で別物

経費精算の文脈で法対応という言葉が出てきますが、中身は分けて考える必要があります。

  • 紙で受け取った領収書をスマホやスキャナで読み取って保存するのが、いわゆるスキャナ保存
  • メールやWebで受け取ったPDFの領収書・請求書をそのまま保存するのが、電子取引のデータ保存

前者は任意で、社内で選べます。後者は電子でやりとりしたものを紙に印刷して保存するだけでは足りない、という扱いになっています。製品によっては、片方にしか対応していないこともあります。「電帳法対応」とだけ書かれた資料を見たら、どちらを指すのかを必ず確かめてください。

あわせて確かめたいのが、日付・金額・取引先で検索できる仕組みになっているかです。そしてもっと実務的な話として、領収書の原本をいつ捨てられるのかは、社内の経費規程を直さないと現場が判断できません。システムを入れただけでは、現場は不安がって原本を机の引き出しに貯め続けます。結局、紙の束が減らないという結果になりがちです。運用開始と同時に、規程改訂と周知をセットで進めるのが確実です。判断に迷う部分は、顧問税理士に事前に確認しておくと安全です。

料金はID課金が中心。使わない人の分をどう数えるか

クラウドの経費精算は、利用人数に応じた月額が一般的です。ここで見落としやすいのが、誰をIDとして数えるかです。

  • 経費を申請する従業員だけでよいのか
  • 承認するだけの役員や部長にもIDが要るのか
  • パート・アルバイトなど、交通費だけ出る人はどう扱うか
  • 見るだけの閲覧権限にも課金されるのか

交通費しか発生しない人まで全員分のIDを買うと、費用の印象が変わります。契約形態も、実際に使った人数で課金するものと、契約した枠の人数で課金するものがあります。後者だと、退職して人数が減っても、更新のタイミングまで下がりません。

初期費用の扱いも確かめる点です。初期設定の支援、承認ルートの構築代行、既存データの取り込みが別料金になっていることがあります。導入支援が有償のプランと無償のプランで、月額だけを比べても比較になりません。見積は、1年目の総額と2年目以降の総額を分けて出してもらうと、稟議の資料としても使いやすくなります。

やめるときに詰まるのは、過去データと領収書の画像

継続契約は、入るときより解約するときに手間がかかります。経費精算はとくにそうです。理由は、保存義務がある書類を預けているからです。

解約後に困るのは次の点です。

  • 過去の申請データをどの形式で出せるか。CSVだけか、領収書の画像も一括で落とせるか
  • 解約後、いつまでログインできるか。即日停止か、猶予期間があるか
  • データ削除のタイミングを、こちらから指定できるか
  • 移行先で読み込める形式かどうか

明細のCSVは出せても、領収書の画像は1件ずつしかダウンロードできない、という作りになっていることがあります。数年分あると、現実的な作業量ではなくなります。契約前に「解約時のデータ出力の手順書はありますか」と聞いてみてください。手順が用意されている会社は、答えがすぐ返ってきます。

あわせて、最低利用期間と解約予告の期間も確認します。年払いで割引を受けた場合、途中解約しても残りは返らない条件が多く見られます。試しに使ってみたい段階なら、月払いで始めて、運用が固まってから年払いに切り替えるほうが身軽です。

会計ソフト・給与への連携は「どこまで自動か」を実物で確かめる

経費精算の効果は、精算そのものより、その後の転記が消えることで出ます。ですから連携の範囲は重要です。

確かめるのは次の点です。

  • 仕訳データを会計ソフトにそのまま取り込める形式で出せるか
  • 勘定科目と部門の割り当てを、自社のルールに合わせて設定できるか
  • 従業員への振込は、銀行の振込データとして出力できるか
  • 給与と合わせて支払う運用にする場合、給与計算側に取り込めるか

「連携対応」と書かれていても、中身はCSVの書き出しと取り込みで、毎月手作業が残ることがあります。悪いことではありませんが、想定より楽にならなかった、という食い違いが起きます。デモの段階で、自社の会計ソフトに取り込むところまで見せてもらうのが確実です。

法人カードの明細取り込みも、よく使われる機能です。カードで支払った分は立替がなくなるので、精算の件数自体が減ります。ただし、カードの発行会社によって連携の可否が変わります。カードの見直しと同時に検討すると、話が早く進むことがあります。

稟議は「削減できるのは現金と時間」で組み立てる

月額が増える提案なので、稟議では効果の説明が要ります。金額の削減だけで説得しようとすると、材料が足りなくなりがちです。

使いやすい論点は次のあたりです。

  • 小口現金をやめられる。手元の現金を数える作業と、合わないときの調査がなくなる
  • 申請と承認の滞留が可視化される。誰のところで止まっているかが分かる
  • 月次の締めが早まる可能性がある。転記の待ち時間が減るため
  • 法改正のたびに様式を作り直す手間が、ベンダー側の更新に寄る

数字を出すなら、自社で確認できるものだけにしてください。たとえば、直近3か月の精算件数、経理が精算処理に使っている概算の時間、小口現金の月末残高。これらは社内で数えられます。他社事例の削減率をそのまま引用すると、後で「そうならなかった」と言われます。

もうひとつ、稟議書に入れておくと通りやすいのが、やめるときの条件です。最低利用期間、解約予告、データの持ち出し方法を1行ずつ書いておくと、決裁者の不安が減ります。逆に言えば、そこを書けない契約は、契約前にもう一度確かめたほうがよい契約です。

導入前にやること、導入後3か月でやること

最後に、進め方を順番に並べます。

導入前

  • 直近3か月の精算件数と、申請者・承認者の人数を数える
  • 承認ルートと金額の基準を紙に書き、経営層に確認する
  • 経費規程の改訂が必要な箇所を洗い出す
  • 候補を2〜3社に絞り、自社データでデモを依頼する
  • 解約時のデータ出力手順、最低利用期間、解約予告を書面で確認する

導入後

  • 最初の1か月は紙と並行にせず、期日を決めて一気に切り替える。並行運用は両方が中途半端になりがちです
  • スマホを業務で使わない従業員向けに、PCからの入力手順を用意する。私用スマホを使ってもらう場合は、同意の取り方を決めておく
  • 3か月目に、承認の滞留が起きている部署を確認し、代理承認の設定を見直す

問い合わせ窓口を総務の1人が抱え込むと、その人が休んだ月に止まります。社内マニュアルは短くてよいので、最初に作っておくと引き継ぎが楽になります。

買う前に確かめること

  • 承認ルートと金額基準を紙に書き、経営層の了承を得たか
  • IDとして課金される対象に、承認者・閲覧者・パートが含まれるか確認したか
  • スキャナ保存と電子取引、どちらに対応した製品かを確かめたか
  • 解約時のデータ出力方法と、領収書画像を一括で落とせるかを書面で確認したか
  • 最低利用期間と解約予告の期間、年払いの途中解約時の扱いを読んだか
  • 自社の会計ソフトへ取り込むところまで、デモで実際に見せてもらったか

よくある質問

領収書の原本は、システムに取り込んだらすぐ捨ててよいですか。

システムを入れただけでは判断できません。スキャナ保存の要件を満たす運用にしたうえで、社内の経費規程に原本の扱いを明記する必要があります。保存や廃棄の可否は自社の状況で変わるため、顧問税理士に事前に確認してから周知するのが安全です。

解約したあと、過去の精算データは見られなくなりますか。

多くは一定の猶予を置いて閲覧できなくなります。CSVでの明細書き出しはできても、領収書の画像を一括で落とせるかは製品によって差があります。契約前に、解約時のデータ出力の手順を書面で確認しておいてください。

スマホを持っていない従業員がいます。導入できますか。

PCのブラウザから申請できる製品が大半なので、運用は可能です。ただし紙の申請書を代わりに書いてもらう例外を作ると、そこだけ手作業が残り続けます。入力を代行する担当を決めるなど、例外の扱いを最初に決めておくのが現実的です。

小口現金は、経費精算システムを入れればなくせますか。

精算を振込に寄せれば、なくす方向には進みます。ただし切手や急な現金払いが残る部署があると、完全にはゼロになりません。現金が必要な場面を先に洗い出して、法人カードやプリペイドで代替できるかを確認してから判断してください。
